DRISHTI-CUAS PRD: v1.1 Architecture & Scoring Patch (SIH PS 26247)This document serves as the mandatory technical addendum to the DRISHTI-CUAS PRD v1.0. It resolves critical architectural contradictions, unifies the scoring taxonomy, and establishes a strict offline-first boundary to guarantee build success during the 36-hour hackathon sprint.   1. Unified 7-Class TaxonomyThe UI, tracking engine, database, and After-Action Review (AAR) confusion matrix must exclusively use the following 7 canonical classes to prevent undefined lookup errors:   UNKNOWN_EVIDENCE_INSUFFICIENTHOSTILE_ATTACKHOSTILE_ISRSWARM_ELEMENTCIVIL_UASBIRDFRIENDLY2. Single-Tier Offline Architecture (V1 MVP)The dual FastAPI/SQLite and IndexedDB sync architecture is deprecated to eliminate loopback CSP restrictions and port binding errors on the evaluation laptop. The MVP must be built as a pure browser-based client.   Frontend Framework: React 19 + TypeScript + Vite.State Management: Zustand (ticking at 20 Hz, rendering Canvas at 60 fps).   Local Persistence: Dexie.js (IndexedDB). All session records, events, and metrics are stored purely in the browser.Backend: None. Eliminate FastAPI and SQLite entirely for the first build.Export: Built-in JSON/CSV download functionality from Dexie.js for instructor evaluation.   3. Responsive 2D UI DimensionsThe fixed 700x700 Canvas viewport inside a 1366x768 layout creates vertical overflow and hides the event log. The UI must be refactored to a responsive, multi-panel flexbox layout:   Center Radar Canvas: 520x520 px (or responsive calc(100vh - 180px)).Left Rail (Track Table): 240px fixed width.Right Rail (F2T2EA Panel): 320px fixed width.Bottom Panel: 8-line scrolling event console.4. Deterministic Replay and Scenario GenerationThe conflict between seeded scenario generation and dynamically injected reactive triggers is resolved via an explicit event-logging architecture.   Logging: Every trainee action, system state change, and dynamically injected reactive trigger must be logged to the Dexie.js events table with an exact simulation timestamp (t_ms).   Replay Execution: The AAR replay mode must not re-run the procedural generation script. It must reconstruct the timeline strictly by iterating over the stored events array to guarantee bit-identical replays.   5. Scoring Edge Cases and Abstracted RubricThe mathematically unbounded penalty stacks in v1.0 are replaced with clamped boundaries and abstracted parameters.   Parameter Abstraction: All effector costs, $P_k$ (probability of kill), and engagement envelopes are declared as "Notional Configurable Parameters" stored in a single config.json file.   Optimal Range Calculation: $R_{opt}$ is defined mathematically as (envelope_min + envelope_max) / 2.   Score Clamping: The global session score and individual track scores are strictly clamped between 0 and 100. No single critical penalty can reduce a track score below 0.   Grade Labels: Change "MISSION-READY" to "Proficient in Simulation" and "REMEDIAL" to "Needs Retraining" to reflect synthetic training boundaries and avoid claims of real-world certification.   Instructions for the development agent: Apply these overrides globally against the v1.0 PRD before initializing the codebase.
